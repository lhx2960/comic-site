| 编号 | 定论 | 理由与影响 |
| --- | --- | --- |
| Q1 | **首页与列表是同一个视图**（`/`），不另设独立列表页 | 只有 3 部漫画，拆两个入口只会让导航更绕；搜索与筛选都发生在首页。F2-1 不算独立导航，改为「首页即列表视图」 |
| Q2 | **保证**每个标签至少命中 1 部漫画 | 标签由数据生成，不手写；导入时校验「无空标签」，测试里直接断言 |
| Q3 | **标签单选**；再次点击同一标签 = 取消；不设「全部」项，用「清除筛选」代替 | 查询与 URL 语义保持简单（`?tag=x`）；多选留到有真实数据量时再评估 |
| Q4 | **只匹配标题与作者**，不匹配标签文本与简介 | 与 D-005 一致；简介搜索属「搜索增强」，已在 §6 不做清单 |
| Q5 | **接续形态**：滚到底部出现「下一话」区块，继续向下即呈现下一话内容并同步更新标题区与地址栏；最后一话底部显示「已是最后一话」+ 返回详情 / 回到顶部。**进入某话的落点规则**：该话存在本地进度 → 从记录页继续；否则从第 1 页开始 | 解决 F4-4 与 F4-6 的矛盾：详情页主按钮随状态变化（无进度 =「开始阅读」，有进度 =「继续阅读：第 x 话 第 y 页」），另给次要入口「从第 1 话重读」 |
| Q6 | 进度粒度 = **漫画 + 话 + 页**；滚动停止（防抖 500ms）后记录；「当前页」口径 = **视口顶部往下的第一张可见页**；读完最后一话标记「已读完」；**提供「清除本机阅读记录」入口**（详情页次要位置） | 给出唯一可判定的口径，测试才能断言；提供清除入口比「让用户去清浏览器数据」更可用，也更好测 |
| Q7 | 列表默认按**数据文件给定的顺序**（导入时写入 `order` 字段） | 本期数据无更新时间/热度字段，按序号稳定排序即可 |
| Q8 | 详情页**不展示**连载状态、阅读量；话列表只显示「话序号 + 话标题」，不显示页数 | 数据里没有这些字段，本期不造；保持详情页信息密度低 |
| Q9 | 站点名**「漫画站」**，首页副标题「示例数据练手的漫画阅读站」 | 用户已默认该名称；如需改名只改文案，不影响结构 |
| Q10 | 详情页显示「继续阅读：第 x 话 第 y 页」 | 与 Q6 的粒度对齐，可被测试断言 |
| Q11 | 示例数据**至少含 1 个带字母的标题**（如「星海 2nd」） | 让 F3-4 的大小写不敏感可被真实验证 |
| Q12 | **做图片级降级**：单张图失败显示「图片加载失败 + 重试」，该页其余内容与后续页仍可读 | 长条滚动下整页失败代价太大；阅读页本来就含客户端交互，单图错误态成本可控 |
| Q13 | 视口从 **360px** 起；浏览器 = 最近两个大版本的 Chrome / Edge / Safari（含 iOS Safari） | G5 需补「浏览器矩阵」落点；E2E 至少在 Chromium 与 WebKit 各跑一次关键路径 |
| Q14 | 首页/列表卡片**不显示**阅读进度标记，进度只在详情页出现 | 卡片保持干净，减少首屏信息量；后续有真实数据再看 |

## 给产品经理的修订要点（供 PRD v1.1）

1. 「上游依据」补 **D-006、D-007**；「下游用途」补 `docs/specs/ui.md`。
2. 新增一条可测 AC 承接 **D-006**：站点页面为浅色底、阅读页为深色底，色值取自 `docs/specs/ui.md` 的设计令牌。
3. 修 F4-4 与 Q5 括注的矛盾（按上面 Q5 的落点规则）。
4. 补 Q2、Q8、Q10、Q13、Q14 的内联 «Q-x» 标注；修正 F4-2 的 «Q9» → «Q8»；给 Q9 找到落点（G7 或首页文案 AC）。
5. F6-2 改为可判定的口径（滚动停止后「视口顶部第一张可见页」为当前页，断言允许 ±1 页）。
6. F2-3 的命中数改为「按示例数据核对」；G4 补「如何可控制造失败/如何判定恢复」的前提；G5 补 Q13 的浏览器矩阵。
7. **G6 键盘可达性保留**，但依据改为「架构师确认（可访问性最低线）」，不再写「依据 D-001」。
8. D-004 的三项配套（图片懒加载、预加载下一话、滚动过程无布局跳动）**补进 F5** 作为 P1 验收标准，不留给设计文档兜底。
