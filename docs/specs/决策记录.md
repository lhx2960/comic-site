## D-003 内容来源 = 示例数据（练手）

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 用户 |
| 状态 | 已定稿 |

- **决策**：本期用**自己准备的示例漫画数据**练手，不接入真实作品库，也不从其他站点抓取。
- **规模（架构师拟定，可改）**：3 部漫画 × 每部 5 话 × 每话 10 页占位图，元数据写成 JSON/TS 文件，由导入脚本灌进数据层。
- **理由**：图片体积与版权问题都不进本期，能把精力放在网页链路本身（路由、渲染、数据获取、阅读体验）。
- **影响**：图片放仓库内静态资源即可，不需要对象存储与上传后台；数据结构要设计成以后能无缝换成真实内容（字段与层级照真实漫画建模）。

## D-004 阅读模式 = 长条滚动

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 用户 |
| 状态 | 已定稿 |

- **决策**：阅读页采用**纵向长条滚动**，一话的页面顺序排下来，滚到底部接下一话。
- **配套（架构师拟定，设计闸门时确认）**：手机优先、桌面可用；图片懒加载 + 预加载下一话；本地记住阅读进度（存浏览器，不需要账号）。
- **理由**：手机端最自然，实现路径清楚，能覆盖 `next/image` 优化、懒加载、滚动进度、状态持久化等真实问题。
- **影响**：阅读页是本期核心页面；数据模型里「话 → 有序页列表」必须稳定有序；图片尺寸与宽高比需入库，避免滚动时布局跳动。

## D-005 搜索范围 = 标题 + 作者 + 标签筛选

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 用户 |
| 状态 | 已定稿 |

- **决策**：搜索支持按**标题**与**作者**关键词匹配；**标签**作为可点选筛选条件，支持「关键词 + 标签」组合。
- **配套**：筛选状态写进 URL（`/comics?q=...&tag=...`），刷新/分享不丢状态。
- **理由**：覆盖「记得名字」与「按题材逛」两种真实找漫画方式，同时把 App Router 的 searchParams 与服务端查询讲清楚。
- **影响**：数据层需要漫画 ⇄ 标签的多对多关系与基础查询；中文分词/拼音搜索不在本期（先用大小写不敏感包含匹配）。

## D-006 视觉基调 = 站点浅色 + 阅读页深色

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 用户 |
| 状态 | 已定稿 |

- **决策**：浏览、列表、详情等站点页面走**浅色**（白底 + 浅灰卡片）；进入**阅读页切换为深色**（近黑背景），让画面成为焦点。本期不做全局主题切换。
- **默认值（架构师拟定，用户未反对即生效）**：站点名沿用「漫画站」、文字 logo；界面语言中文；配色为克制的黑白灰 + 单一主色点缀；具体色值由设计令牌定义，在设计定稿闸门确认。
- **理由**：把复杂度花在读漫画的核心页面上，其余页面保持简单，交付更稳；全局双主题留待下一期。
- **影响**：阅读页需要独立的深色样式域（不污染站点浅色样式）；色值必须集中成设计令牌，禁止在组件里散写十六进制颜色。

## D-008 派发优先级：已有角色会话 > 子代理

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 用户 |
| 状态 | 已定稿 |

- **决策**：凡是**已有同名角色会话**的身份（漫画站-产品经理 / 漫画站-全栈 / 漫画站-测试 / 漫画站-运维），任务一律投递到对应会话执行（`codex queue --thread ...`），**不得用子代理替代**。
- **理由**：用户希望每个身份在自己的会话里积累上下文、可追踪、可续接；子代理跑完即散，身份无法沉淀。
- **影响**：架构师的「通道 A 子代理」仅用于没有对应会话的任务（如一次性 UI 设计）；投递给角色会话的任务单里要写明「不要开子代理，自己完成」。
- **例外**：D-007 的 UI 设计任务（无对应会话）仍按一次性子代理执行。

## D-011 深色阅读域次要按钮描边按无障碍标准修正

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 架构师（依据 T-002 回报的遗留项 2，用户已授权不逐步请示） |
| 状态 | 已定稿 |

- **问题**：深色阅读域次要按钮（`.btn-ghost`）描边对底色仅 1.70:1，低于 WCAG 1.4.11 对可交互控件视觉边界要求的 3:1。
- **决策**：描边令牌改为 `#6E7683`（对深色底 4.25:1）。零成本、只改一处令牌。
- **影响**：`docs/specs/ui.md` §3.2 与 `src/app/globals.css` 的深色域描边令牌必须一致；T-009 可在 WebKit 上复核。

## D-012 封面占位沿用页图，卡片按 2:3 裁切

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 架构师（裁决 T-003 回报的遗留问题 1） |
| 状态 | 已定稿 |

- **冲突**：T-003 验收要求 `public/comics/**` 恰好 150 张 SVG，而 `ui.md` §3.6 推荐封面单独出 2:3（600×900）；两者不能同时满足。
- **决策**：**封面继续复用第 1 话第 1 页**（600×800），生成脚本不新增封面文件；卡片用 `aspect-[2/3]` + `object-cover` 裁切。数据模型 `Comic.cover: ImageRef` 不变，接入真实内容时再给独立 2:3 封面。
- **理由**：界面效果一致，避免改生成脚本、改测试断言、改验收口径的连锁返工；封面比例属于内容资产问题，不是结构问题。
- **影响**：T-004 卡片实现按 2:3 容器 + 裁切；T-003 的「恰好 150 张 SVG」验收口径保持不变。
