## D-016 接下一话的地址同步用 `history.replaceState`（不用 `router.replace`）

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 架构师（裁决 T-007 回报的遗留问题 1） |
| 状态 | 已定稿 |

- **问题**：`router.replace()` 会让 App Router 重新渲染服务端组件，正在滚动阅读的 `ReaderStrip` 被卸载重挂载——已追加的话丢失、滚动位置跳动、进度可能被覆盖。
- **决策**：**采用 `history.replaceState`** 同步地址栏（不新增历史记录、不触发重挂载）。代价是 Next 内部路由状态与地址栏可能短暂不同步（例如 `usePathname()` 不会立刻反映新话号），但页面不依赖它；硬刷新后由服务端按 URL 正确渲染。
- **附加约定**：地址栏**跟随当前阅读到的话**（向上滚回第 3 话时地址回到第 3 话）；`finished`/进度按 `storage.md` 记录。
- **必须被测试覆盖（已写进 T-009）**：滚到第 4 话后 ① 点「返回详情」能正常导航；② 硬刷新后落在第 4 话；③ 浏览器后退能回到进入阅读页之前的页面。
- **另记**：T-007 顺带修掉 T-006 的一个真缺陷（预取状态变化触发 effect 重订阅时，会把「滚动停止 500ms 写进度」的定时器清掉，导致进度静默丢失），并只对 T-006 的测试文件补了一个 `fetch` 桩；已核实其改动范围。

## D-017 加了根级 `loading.tsx` 后，`notFound()` 页面返回 200：接受并记录

| 字段 | 内容 |
| --- | --- |
| 日期 | 2026-09-25 |
| 决策人 | 架构师（裁决 T-008 回报的遗留问题 1） |
| 状态 | 已定稿 |

- **现象**：根级 `loading.tsx` 让响应进入流式模式，HTTP 头在骨架刷出时就发出（200），随后 `notFound()` 只能改渲染内容、改不了状态码。实测：`/comics/nope`、`/comics/xinghai/9` 返回 **200 + 「内容不存在」页面**；未定义路由（`/whatever`）仍返回 **404**。
- **决策**：**接受现状（方案 c）**——保留骨架加载态，404 语义由页面内容表达。
- **理由**：PRD G3 只要求「显示内容不存在提示 + 返回入口、不白屏、不出现堆栈」，**没有**对 HTTP 状态码提要求；`routes.md` 对状态码的硬要求只覆盖 Route Handler（已按 200/404/500 正确实现）。而方案 a（去掉 `loading.tsx`）会牺牲 PRD/`ui.md` 要求的加载态，方案 b（路由组绕开 Suspense）是为一个未被要求的行为做结构改造。
- **影响与后续**：T-009 的 E2E 断言 **UI 行为**而不是状态码；等接入真实内容、需要 SEO 时，再按方案 b 做路由组重构（已记入 `design.md` §14 风险表）。

- **理由**：手机端阅读页的每一像素都该给画面；站点名属于「站点身份」，在沉浸阅读态让位给「我在读哪一话」更合理。G7 的意图（导航不迷路）由「返回详情」入口满足。
- **影响**：由产品经理会话修订 PRD 措辞（不改任何验收行为）；T-009 的 E2E 断言保持不变。
