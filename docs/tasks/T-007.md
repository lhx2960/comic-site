## 背景

D-004 要求「一话读到底不断档」；Q5 定下形态：滚到底出现「下一话」区块并继续向下接续，同时更新标题区与地址栏；最后一话显示收尾提示。接口契约见 `docs/contracts/routes.md`。

## 要做的事

1. `route.ts`：`GET /api/comics/[slug]/chapters/[chapter]`，返回 `ChapterDetail` JSON；参数非法或不存在 → 404 `{"error":"not_found"}`；未预期异常 → 500
2. 预取（F5-11）：当前话剩余不足一屏时，客户端提前 `fetch` 下一话数据（图片尚未必要，但接口数据要先到）
3. 追加渲染：滚到底把下一话的页面追加到同一滚动容器，视觉连续；追加后标题区显示新话序号
4. 地址同步：`router.replace(..., { scroll: false })` 更新为下一话路由（不新增历史记录）
5. 最后一话（F5-5、F5-7）：底部显示「已是最后一话」+ 返回详情 / 回到顶部；不再请求下一话
6. 接口异常降级：404/500 时显示「下一话暂时取不到 + 重试」，不破坏已读内容
7. 单测：接口参数校验与状态码分支（可用 route handler 直接调用）
8. 中文注释：重点解释「Route Handler 与 Server Action 的区别」「为什么这里用客户端 fetch 而不是服务端渲染」
