## 背景

首页即列表视图（Q1），承载「逛」与「找」两条路径；筛选状态全部由 URL 承载（D-005）。视觉规格见 `docs/specs/ui.md` 的首页章节（移动优先，390px 基准）。

## 要做的事

1. `page.tsx` 为服务端组件，读 `searchParams`（注意：Next.js 中它是异步的）调用 `listComics({ q, tag })` 与 `listTags()`
2. 结构：站点 hero（站点名 + 副标题 + 搜索框）→ 标签筛选条（横向滚动、不换行、单选、再次点击取消）→ 结果计数 → 卡片网格
3. `SearchBox` 为客户端组件：受控输入 + 提交后写入 URL（`q`），清空即移除参数
4. 卡片网格：手机 2 列、宽度 ≤340px 退化单列横向卡、桌面 3 列；封面 2:3 用 `next/image`，无布局跳动
5. 生效筛选的标识 + 「清除筛选」；0 条结果走 `EmptyState`（含清除入口）
6. 单测：URL 参数 → 查询条件 → 结果数量等纯逻辑；组件层可测关键渲染分支
7. 中文注释（硬规则 7），重点解释「searchParams 为什么是异步的」「为什么筛选状态放 URL」
