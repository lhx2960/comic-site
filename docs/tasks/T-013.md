## 背景

架构师终验收发现：T-009 的 E2E 跑在 `pnpm dev` 上，而**同一份代码在 dev 与生产构建下行为不一致**（`/comics/xinghai/9` 的 404 文案一个对、一个错，缺陷已由 T-012 修复）。据此立规矩 **D-019：E2E 一律验证要发布的产物**。本任务落实这条规矩并重跑全量，作为交付前的最后一轮验证。

## 要做的事

1. 把 `playwright.config.ts` 的 `webServer` 从 `next dev` 改为**生产构建**：
   - 形如 `command: "pnpm build && pnpm start --port 3100"`（注意把 build 的耗时计入 `timeout`，并保留 `reuseExistingServer` 在本地为 true、CI 为 false）
   - 启动前确保没有残留的 dev server 占用端口（可用 `--port` 固定端口 + 失败时给出清晰报错）
2. Playwright 的产物目录继续留在仓库外（沿用现有的 `%TEMP%\comic-site-e2e` 方案），避免写 `test-results/` 触发 dev 重编译（F-04）
3. 重跑全量：`pnpm e2e`（Chromium 全量 + WebKit 关键路径），确认 **102/102**
4. 重点复核四条在**生产构建**下的表现并单独贴输出：`F5-9`（这一话不存在）、`F5-4b`（T-011 的留痕用例）、`D-016-①/②/③`（地址同步三条）、`F5-10/F5-12`（懒加载与无布局跳动）
5. 报告中写清「T-009 结论（dev）」与「T-013 结论（prod）」的差异；若任何用例在 prod 下失败，**保留红灯**并给最小复现步骤，不要放宽断言
