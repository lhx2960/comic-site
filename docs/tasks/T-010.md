## 背景

项目目标是 Vercel 部署（design.md §13）。本期无数据库与密钥类环境变量，CI 应至少覆盖类型检查、Lint、单测、构建，E2E 可视耗时决定是否纳入。

## 要做的事

1. GitHub Actions 工作流：安装（pnpm + Node LTS + 缓存）→ `type-check` → `lint` → `test` → `build`；（可选）E2E
2. 验证工作流在本地可执行的部分（至少 `pnpm build` 与脚本命令能跑通，并给出发起方式）
3. `docs/ops.md`：环境变量清单（本期预计为空，需明确写出）、本地启动、部署步骤、**回滚步骤**、监控与日志入口（Vercel 自带）
4. 若本机已有 Vercel 登录（`vercel whoami` 可验证）且用户同意，跑一次预览部署并记录 URL；**没有登录就只交付可执行步骤并标注阻塞**
5. 不把任何密钥写进仓库或文档

## 验收标准

- [ ] CI 配置文件语法合法，且各步骤命令与 `package.json` 脚本一致
- [ ] `docs/ops.md` 含：环境变量清单、部署步骤、回滚步骤、日志入口
- [ ] 回滚步骤至少被**演练一次**（可用 `vercel rollback` 的 dry-run 或本地等价操作说明 + 证据）
- [ ] 仓库中不出现任何密钥（`git grep` 佐证）
- [ ] 若完成真实部署，附可访问 URL 与 `vercel ls` 输出

## 约束

- 只改「可改目录」内的文件；不改业务代码与契约
- 密钥只走平台环境变量；不得写入仓库、文档或回报
- 不要开子代理；完成后落盘 `docs/reports/T-010.md`

## 回报要求

状态（被阻塞时说明缺什么凭据）+ 证据（命令与输出）+ 改动文件 + 验收逐条核对 + 遗留问题。
