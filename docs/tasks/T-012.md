## 背景（架构师实测证据）

PRD **F5-9** 要求：打开不存在的话时显示「**这一话不存在**」+ 返回该漫画详情的入口。

- **dev 下正确**：T-009 的 E2E（跑在 `pnpm dev` 上）断言 `heading=这一话不存在` 且 **通过**。
- **生产构建下错误**：我 `pnpm build` 后用 `next start` 实测：

```
GET /comics/xinghai/9   → 200  文案出现「这部漫画不存在」（slug 级 not-found），无「这一话不存在」
GET /comics/xinghai/01  → 200  同上（前导零，routes.md 要求按不存在处理）
GET /comics/nope/1      → 200  同上（漫画本身不存在，这条文案可接受）
```

即：**生产构建把 `[chapter]/page.tsx` 里的 `notFound()` 交给了上一层（`[slug]`）的 not-found 边界**，导致文案与出口都指向「漫画不存在」，而漫画其实是存在的。

## 要做的事

1. 让「不存在的话」在生产构建下也渲染「这一话不存在」+「返回详情（`/comics/{slug}`）」：
   - 推荐做法：**不再依赖 notFound() 的边界选择**——在 `[chapter]/page.tsx` 里对「格式非法」或「数据里没有这一话」的情况**直接渲染话级空状态**（复用 `EmptyState`），保持 URL 与状态码现状（D-017 已裁定流式下为 200）。
   - 若你判断能用更小的改动让边界在生产构建下正确选择，也可以，但必须在**生产构建**下自证。
2. `/comics/nope/1`（漫画本身不存在）保持「这部漫画不存在」+「去漫画库/返回首页」不变。
3. 未定义路由 `/whatever` 仍必须是真 404（不要动根级 `not-found.tsx` 的行为）。
4. 补单测覆盖两条分支（格式非法 / 数据无此话）渲染的是「这一话不存在」，并说明它与 slug 级文案的区别。
