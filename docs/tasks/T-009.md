## 背景

按角色章程，测试独立验证「产品是否真的符合验收标准」，不采信实现者自述。需求依据是 `docs/specs/prd.md` v1.1（45 条 F-AC + G1～G10），视觉依据 `docs/specs/ui.md`，行为契约 `docs/contracts/routes.md`、`storage.md`。

## 要做的事

1. 搭建 Playwright（Chromium + WebKit），能在本地对 `pnpm dev` 起的站点跑用例
2. 写 E2E 覆盖以下主路径与边界（每条对应 PRD 编号）：
   - 首页浏览与卡片信息（F1-1、F1-2、F1-4）
   - 标签筛选、刷新保持、跨窗口分享保持、清除筛选、空结果（F2-3 ～ F2-9）
   - 搜索：完整标题、作者、片段、大小写不敏感、无匹配、首尾空格（F3-1 ～ F3-8）
   - 详情：元信息与话列表顺序、进入某话、不存在内容（F4-1、F4-2、F4-3、F4-5）
   - 阅读页：页序、无横向滚动、滚到底接下一话、最后一话收尾、非法话序号（F5-1 ～ F5-9）
   - 进度：读几页后重进从记录页继续、清除记录（F6-1 ～ F6-3、F6-7）
   - 全局：空状态、404、错误态重试、键盘可达、深色阅读页与浅色站点（G2、G3、G4、G6、G10）
3. 产出一张「验收标准 → 用例名 → 结果」映射表，未自动化的条目写清原因与手工步骤
4. 失败项写最小复现步骤；不修改业务代码（发现缺陷回报架构师）

## 验收标准

- [ ] `pnpm e2e` 可重复执行并稳定（附完整输出）
- [ ] 映射表覆盖 PRD 全部 F-AC 与 G1 ～ G10，未覆盖项有原因
- [ ] 至少 Chromium 全量、WebKit 关键路径各跑一次（附输出）
- [ ] 失败项（若有）有最小复现步骤与归属建议
- [ ] 不改任何 `src/**` 文件（`git status` 证明）

## 约束

- 只改「可改目录」内的文件；不改契约、不改业务代码
- 需要新增依赖时只加 `@playwright/test` 相关，并在回报里列出版本
- 不要开子代理；完成后落盘 `docs/reports/T-009-验证.md`

## 回报要求

状态 + 证据（命令与输出）+ 改动文件 + 用例通过/失败统计 + 失败项复现步骤。
