## 背景

测试会话用 E2E 找出一个真实缺陷：**停在文档底部时下一话不会自动接续**。

- 现象与最小复现：见 `docs/reports/T-009-验证.md` §5 F-01（Chromium 与 WebKit 均复现）。
- 根因：`ReaderStrip` 把「话末区块进入视口 → 追加下一话」的判定只写在 `scroll` 事件回调里；预取数据是在滚动停止之后才回来的，此时不再产生新的 `scroll` 事件，追加逻辑永远没有机会执行。连续慢速滚动时数据在滚动过程中就回来了，所以主路径正常。
- 同源脆弱点 F-02：进度写入（500ms 防抖）同样只由 `scroll` 事件驱动。
- 留痕用例：`e2e/reader.spec.ts` → `F5-4b【缺陷 F-01】…`（当前预期红灯，修好后应转绿，**不要改这条测试**）。

## 要做的事

1. 把「话末区块是否已进入视口」的判定从纯 `scroll` 回调中解耦：例如在 `nextChapter` / `nextStatus` 变为 ready 时补一次判定，或给话末区块挂 `IntersectionObserver`（与懒加载同一套机制）；两种做法都行，选可读性和可测性更好的那种
2. 用同一机制兜底进度写入：如果滚动停止后没有新的滚动事件，也要能写入当前页（F-02）
3. 保持既有行为不变：懒加载仍按需请求、`finished` 按 `storage.md`（最后一话 + 距底部 ≤24px）、地址同步仍走 `history.replaceState`（D-016）
4. 补单测：至少覆盖「数据后到 + 停在底部」这条路径（模拟预取在滚动停止后才 ready）
