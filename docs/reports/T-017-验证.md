### 3.1 重跑第 2 轮的孤例红灯：`G7 阅读页有返回详情入口（回首页需经详情页两跳）`

**位置**：`e2e/global.spec.ts:310`，project = `chromium`（T-009 起就有的旧用例，**未做任何改动**）。

**失败断言**：点阅读页顶栏的「‹ 返回详情」之后：

```
Error: expect(page).toHaveURL(expected) failed
Expected pattern: /\/comics\/xinghai$/
Received string:  "http://127.0.0.1:3100/comics/xinghai/3"
```

即：点了一次「返回详情」，地址栏与页面都留在阅读页，15 秒不动；失败快照仍是阅读页顶栏
（`link "返回详情" → /url: /comics/xinghai` + 「星海拾遗」+ 第 3 话）。

**现场**：

```
%TEMP%\comic-site-e2e-archive\t017-final-r2\artifacts\global-G7-导航与站点标识-G7-阅读页有返回详情入口（回首页需经详情页两跳）-chromium\
  error-context.md / test-failed-1.png / trace.zip
```

**trace 证据**（与被点链接同 URL）：

```
31745.856 200 fetch  /comics/xinghai?_rsc=c3sMdOKXC7RC8IVH     ← 该链接的预取，先完成
31813.088 200 fetch  /comics/xinghai?_rsc=m0Q3Mj8Qx4b8colq    ← 点击触发的导航 RSC，也 200
31825.073 200 script /_next/static/chunks/app/comics/%5Bslug%5D/page-087d34e9159c9061.js   ← 目标路由 chunk 也 200
→ 之后 15 秒 URL 始终停在 /comics/xinghai/3，没有 pushState、没有 console 报错
```

**判定**：与 F-06 / T-016 §5.2 的 `G6` **完全同一签名**（导航 RSC 与目标 chunk 都到手，但路由没有提交）。
共同点：被点的链接都是**仍保留默认预取**的站内 `<Link>`（这里是阅读页顶栏的「返回详情」/「详情」，
D-021 只关了**详情页**上的链接）。与本次 `D-016-②` 的断言收窄无关。

```

  20 passed (36.5s)
```

即与 `G6` 一样是**稀有 + 时序相关**，隔离跑抓不到。

**环境备注**：重跑期间另一个会话也在同一仓库跑 E2E/构建，我因此遇到两次环境性失败
（复用正在退出的服务 → `ERR_CONNECTION_REFUSED`；并发 build 抢 `.next` → `ENOENT build-manifest.json`）。
这两次不是用例结果，已在等对方跑完后重跑；上面 3 轮都是独占仓库时跑的。
