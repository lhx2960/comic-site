**内部矛盾 1 处（与决策无关，属 PRD 自洽性）**：F4-4「点击『开始阅读』→ 进入第 1 话阅读页」与 §8 Q5 当前取值里的括注「从详情进入某话一律从该话第 1 页开始（**除非存在本地进度**）」互相打架；F4-6 / F6-3 又要求有进度时出现「继续阅读」入口。三者叠加后「本机已有进度时点『开始阅读』去哪」没有唯一答案，测试无法判定。

### 2. 有没有少做

1. **D-006 整条漏承接（阻塞级）**：站点浅色 / 阅读页深色、色值集中为设计令牌，是用户可见且可测的要求；PRD 自称下游「唯一需求依据」，却对它零覆盖，也没写「本条由 `ui.md` 承接」。下游测试工程师会找不到依据。
2. **依据表与下游用途表陈旧（阻塞级，代价极低）**：「上游依据」停在 D-001 ～ D-005；D-006（`da17c8b`）、D-007（`66ad499`）都早于本 PRD 的交付提交 `c8dd9f5`（证据 3），不是时序问题。「下游用途」应补 `docs/specs/ui.md`，与 D-007 的「设计定稿闸门同时看架构设计 + UI 规格 + 预览截图」对齐。
3. **D-004 三项配套无入口（建议级）**：图片懒加载、预加载下一话、避免滚动时布局跳动（证据 6 全零命中）。前两项可用测试观察判定，第三项可用「滚动过程无内容位移」判定；建议补 1 ～ 2 条 F5 验收标准，或显式写明由 `design.md` / `ui.md` 承接，避免「决策说了但没人做」。
4. §6「不做」清单覆盖 ≥ T-001 要求（账号、收藏、评论、付费、后台管理、上传、真实作品入库均有），未发现少写。

### 3. 有没有多做

1. **G6 键盘可达性（P1）无决策依据**：D-001 ～ D-007 均未提无障碍，但 §3 总览把它标注为「依据 D-001」。这是本 PRD 唯一超出决策范围的新增要求。建议架构师显式确认保留（成本低、对质量有益），否则删除或降为建议项；无论哪种，都应改掉「依据 D-001」这个不成立的引用。
2. 其余条目（F6 进度记忆、G4 加载失败与重试）都能追溯到 D-004 配套项，且 F6/G4 已分别标 P1 与 «Q12»，不算多做。

### 4. 验收标准是否可测试

**可测试性总评**：45 条 F-AC 全部采用「输入/操作 + 预期结果」两列表，无形容词（证据 8）；G1 ～ G9 给出判定方式。整体写法合格，以下 5 类问题需修：

1. **13 条 AC 取值未定稿（可闭合）**：F2-1、F2-8、F3-4、F3-8、F4-2、F4-6、F5-4、F5-5、F5-7、F6-3、F6-6、F6-7、G4 带 «Q-x»。架构师答复 Q1 ～ Q14 后即可定稿，不属缺陷。
2. **追溯缺口（形式缺陷）**：Q2、Q8、Q10、Q13、Q14 没有任何 AC 内联标注，但取值已写进正文 —— Q2 → F2-9/G2；Q8 → F4-1/F4-2；Q10 → F4-6；Q13 → G5；Q14 → F1-1/F2-1。与 §4 写法约定「带 «Q-x» 的条目取值尚未定稿」不一致，评审者无法一眼看出这些条目也在等确认。
3. **编号引用错误**：F4-2 标注的是 «Q9»，但 Q9 是「站点名称与首页文案」（其影响列写的是 G7 与文案类验收）；与 F4-2 对应的是 Q8（「话列表是否显示每话页数」，其影响列写的正是 F4-1、F4-2）。疑为笔误，应为 «Q8»。附带：Q9 目前是孤儿项 —— G7 无标注，首页副标题在任何 AC 里都没有落点。
4. **F6-2 期望值不唯一**：「允许 ±1 页误差」叠加 Q6 的「滚动停止后记录当前可见页」，但没有定义「当前可见页」的判定规则（跨页各半、同屏多页时算哪页）。测试无法给出唯一期望值，建议改为可判定的口径（例如「以视口顶部起第一张可见页为当前页，断言页允许与记录页相差 1 页」）。
5. **两处依赖未定稿数据/前提**：F2-3 把标签命中数写死为「示例数据中命中 2 部」，而示例数据尚未定稿；同文档 F1-4、F3-2 用的都是「按数据核对」，写法应统一。G4「恢复后点击重试可成功加载」没有说明测试如何可控地制造失败、如何判定「恢复」，需要补一句可复现前提，否则该条不可执行。另：Q13 的浏览器矩阵（Chrome / Edge / Safari 最近两个大版本）在 G5 中完全没有落点。
