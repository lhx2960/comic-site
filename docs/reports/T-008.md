## 遗留问题与建议

1. **有了根级 `loading.tsx` 之后，404 页面的 HTTP 状态码从 404 变成了 200（需要你裁决）**。
   实测对比：

   ```
   T-005 时期（还没有 loading.tsx）：/comics/no-such-comic -> status=404
   现在（有 src/app/loading.tsx）  ：/comics/no-such-comic -> status=200
   ```

   原因已定位：`app/loading.tsx` 会在这一段外面建立 Suspense 边界，于是响应变成
   流式（实测 `Transfer-Encoding: chunked`，HTML 里同时含骨架与「内容不存在」内容）。
   Next.js 对**流式响应**固定返回 200 —— 状态码在骨架刷出的那一刻就已经发出去了，
   后面的 `notFound()` 无法再改。

   影响面：PRD F4-5/G3 只要求「显示提示 + 返回入口、不出现堆栈与白屏」，页面表现是对的；
   契约里对**状态码**有硬要求的只有 Route Handler（`routes.md` 的 200/404/500），那部分由
   T-007 的单测覆盖，未受影响。真正的代价是 SEO/语义：不存在的作品页会以 200 返回。

   可选修法（都需要动 T-008 可改目录之外的文件，故未自行决定）：
   a. 去掉根级 `loading.tsx`（回到没有骨架，但 404 状态码恢复）；
   b. 把骨架下沉到各路由段，同时把首页放进路由组（`app/(home)/…`），让 404 路径不被根级
      Suspense 包住；
   c. 接受现状（页面体验优先）。
   **请给一个方向，我按你的选择再做一次（工作量都很小）。**
2. **逐作品的 404 文案还没做**：`ui.md` §5.3 要求「这部漫画不存在」「这一话不存在」，
   这需要 `src/app/comics/[slug]/not-found.tsx` 与 `src/app/comics/[slug]/[chapter]/not-found.tsx`
   两个新文件，不在 T-008 的可改目录内。现在统一落到全局「内容不存在」页（文案与出路都对，
   只是没有点出具体是哪一部/哪一话）。
3. **`overscroll-behavior-y: contain` 仍未落地**：它必须写在 `html/body` 上，属于
   `globals.css`（单写者文件，不在 T-008 可改目录）。阅读页手机端滚到底继续滑时，
   理论上会有轻微橡皮筋/下拉刷新（Chrome 有 `overscroll-behavior` 就无法完全避免）。
   一行 CSS 即可：`body { overscroll-behavior-y: contain }`，如果你同意，我可以在下次改动里带上。
4. **文案集中到 `src/lib/copy.ts`（ui.md §10.9）依然没做**：`src/lib/**` 不在任何一张任务单的
   可改目录里。现在同一句话（例如「网络或数据服务暂时不可用，请稍后重试。」）在
   `error.tsx`、`ReaderStrip.tsx` 各写了一次，`EmptyState` 的调用处也各写一次。
   建议给一张小任务单，把空/错误/按钮文案收进一个常量文件。
5. **组件提取（D-014）仍未做**：`SiteHeader`（首页/详情/阅读页三套顶部条）、
   `ProgressCard`/`PrimaryCta`（现在合在 `ProgressCTA`）、`HeroTitle`/`SectionHeading`/`FilterSummary`/`ComicGrid`
   （现在内联在 `page.tsx`）都还需要提取，而它们分散在 T-004/T-005/T-006 的可改目录里，
   T-008 只给了 `layout.tsx` 与 `components/**`，无法跨文件重构。建议单独派一张「结构性重构」任务。
