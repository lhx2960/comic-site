```ts
  const consoleErrors: string[] = [];          // 新增：收集 console error / pageerror
  page.on("console", (message) => { if (message.type() === "error") consoleErrors.push(message.text()); });
  page.on("pageerror", (error) => consoleErrors.push(`pageerror:${error.message}`));

  await page.goto("/comics/xinghai/3");
  await expect(page.locator('img[alt="第 3 话 第 1 页"]')).toBeVisible();
  await page.waitForTimeout(500);

  await sectionBlocks(page, 4).first().evaluate((el) => el.scrollIntoView({ block: "start" }));
  await expect(readerHeader(page)).toContainText("第 4 话");
  await expect.poll(() => page.url()).toMatch(/\/comics\/xinghai\/4$/);
  expect(consoleErrors, "接续过程不应产生控制台错误").toEqual([]);

```

## 5. 红灯清单（保留，未改断言）

### 5.1 `D-016-②` 的越界断言（需架构师裁决）

**现象**（第 1 轮全量）：`D-016-② 滚到第 4 话后硬刷新，仍落在第 4 话` 在最后一句
`await expect(pageBlocks(page)).toHaveCount(10)` 失败：

```
Error: expect(locator).toHaveCount(expected) failed
Locator:  locator('[data-page-index]')
Expected: 10
Received: 20
Timeout:  15000ms
```

失败现场快照显示：顶栏 `第 4 话 · 日志第七页`、URL `/comics/xinghai/4`，
但页面里多出 `region "第 5 话 回信"` —— **硬刷新后第 5 话被自动接上了**（20 = 第 4 话 10 页 + 第 5 话 10 页）。

**诊断（一次性脚本，已删除）**：

```
BEFORE-RELOAD record = null                       ← 500ms 防抖还没落盘，没有本机进度可恢复
BEFORE-RELOAD state  = {"url":"/comics/xinghai/4","scrollY":9735,"scrollHeight":19467,"pageBlocks":20,...}
AFTER-RELOAD  record = {"xinghai":{"chapter":4,"page":10,"finished":false,...}}
AFTER-RELOAD  state  = {"url":"/comics/xinghai/4","scrollY":9069,"scrollHeight":9789,"pageBlocks":10,...}
```

原因链：刷新前文档是 20 块（第 3+4 话）、滚动位置在 9700+px；`page.reload()` 后浏览器会把滚动偏移
**恢复到新文档**，而新文档只有第 4 话（9789px），偏移被夹到 9069px ≈ 第 4 话末尾 → 阅读器判定
「剩余不足一屏」→ 预取并接上第 5 话 → `[data-page-index]` 变成 20。

**判定**：`D-016-②` 的实质「硬刷新后仍落在第 4 话」**通过了**（URL + 顶栏都是第 4 话）；
失败的是用例里额外加的「页面里只能有 10 个页块」——它描述的是「刷新后不会自动接下一话」，
而这正是 F5-4 / D-021 明确要有的行为。**属于测试的过度断言，不是产品缺陷。**

**复现率**（隔离跑，生产构建）：

```
> pnpm exec playwright test -g "D-016-②" --project=chromium --workers=3 --repeat-each=10 --reporter=line
  2 failed
  8 passed (57.0s)          ← 2/10 命中，失败签名固定为「20 blocks instead of 10」
```

**为什么不在本轮直接改**：这是 `F5-4b` 之外的断言，超出你给的授权范围（「其它红灯一律保留回报我」），
所以保持原样并交回裁决。若追认，最小改法是二选一：

```ts
// 方案 A（推荐）：只数第 4 话自己的页块
await expect(sectionBlocks(page, 4)).toHaveCount(10);
// 方案 B：不限制是否已接上第 5 话，只保证本话页块齐备
await expect(sectionBlocks(page, 4)).toHaveCount(10);   // 语义同 A，去掉全局计数
```

### 5.4 附带观察（不判为缺陷，仅记录）

- 刷新前若 500ms 防抖没落盘（例如刚点进某话就立刻刷新），本机进度为空 → 阅读器不做应用级恢复，
  只能依赖浏览器的滚动恢复，落点可能偏到本话末尾（上例就是第 4 话第 10 页）；随后写入的记录是
  「第 4 话第 10 页」，**与用户刷新后实际看到的位置一致**，没有自相矛盾。
- 若进度已落盘，应用级恢复（`scrollIntoView` 到记录页）会覆盖浏览器的滚动恢复，落点即记录页。
