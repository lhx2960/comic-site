## 遗留问题与建议

1. **契约需要补一条：`finished`（已读完）的触发条件**。`storage.md` 的「当前页」口径是「视口顶部往下第一张可见页」，而末页下方只留 56px 底栏空间 —— 在常见视口高度下，滚到底时**倒数第二页的底边仍在视口顶部之下**，于是末页永远不会成为「当前页」。实测 390×844：读完第 5 话滚到底，记录的是 `page:9`。也就是说按字面规则 F6-7 永远不会触发。
   本次的处理（已在 `ReaderStrip.tsx:62-75` 注释里写明）：`page` 严格按字面口径；`finished` 追加「滚动位置到达文档底部（±24px）」这一条补充条件。实测 `{chapter:5,page:9,finished:true}`，回滚后 `finished` 保持。
   **建议**：把这条写进 `storage.md`（例如「读到最后一话且滚动到底 → finished: true」），否则下一个实现者会踩同一个坑。这是我唯一动到契约解释的地方，没有改契约文件。
2. **`overscroll-behavior-y: contain` 与 `viewport-fit=cover` 需要 T-008 补**：前者必须落在 `html/body` 上（写在页面容器里无效），后者要写进 `layout.tsx` 的 viewport 元数据；两者都是 `layout.tsx` / `globals.css` 的改动，不在 T-006 可改目录内。现在 `env(safe-area-inset-bottom)` 会取到 0（因为没有 `viewport-fit=cover`），所以在真机上底栏会紧贴屏幕底边 —— 值是安全的，只是少了「下巴」留白。
3. **T-007 的接缝已经留好**：`ReaderStrip.tsx:91-92` 目前是单元素常量 `sections`，T-007 把它改成 state 后即可把下一话 append 进同一条滚动流；`:337` 是页尾插槽位置，`:126-135` 的当前页测量按 DOM 顺序取，天然支持多段。
4. **客户端组件继续增加**：本任务新增 3 个客户端组件（`ReaderStrip`、`RetryableImage`、`ReaderProgressBar`），加上前序的 `SearchBox`、`ProgressCTA`、`ChapterList`，全站已有 6 个客户端边界。这与 design.md §5 的「本期只 3 个」有明显出入，但本任务的三项能力（IO、scroll、localStorage）都只能在客户端。建议 T-008 或后续任务里评估是否把 `ReaderProgressBar` 合并进 `ReaderStrip`（少一个边界）。
5. **`page` 在视口很短时的表现**：视口高度 ≤536px 时，末页会成为「当前页」（因为末页能滚到视口顶部之上），此时记录 `page:10` 也符合字面规则；这与上面第 1 条的补充条件不冲突，但说明页码会随视口高度略有差异，验收时按 F6-2 的 ±1 页宽容处理。
