## 遗留问题与建议

1. **`ui.md` 要求标签用 `<button aria-pressed>`，与 `design.md` 的客户端组件预算冲突（需裁决）**：`ui.md` §7.4/§10.10 规定「标签是 `<button aria-pressed>`（回车/空格切换）」，但那需要 `onClick` 才能改 URL，就会让 `TagFilter` 成为第 4 个客户端组件，违反 `design.md` §5「本期只 3 个客户端组件（SearchBox / ReaderStrip / RetryableImage）」。本次选择服务端 `<Link>` + `aria-current="true"`：仍是原生可点元素、Tab/Enter 可用、URL 驱动、可中键新标签页打开，且多花 0 字节 JS。若要以 `ui.md` 为准，请给一个任务把 `TagFilter` 改成客户端组件（会与 `SearchBox` 合并成一个「筛选岛」更省 JS）。
2. **`ui.md` 的 5 个组件在 T-004 里以标记形式就地渲染（需确认）**：`SiteHeader` / `HeroTitle` / `SectionHeading` / `FilterSummary` / `ComicGrid` 都不在 T-004 的「可改目录」（只列了 `page.tsx` + 4 个组件），而任务单又要求「新建公共组件时先回报架构师」。为不越界，它们写在 `page.tsx` 里（`page.tsx:49` 吸顶头、`:65` 首屏、`:97` 分节标题、`:73` 条件摘要、`:105` 网格），并留了注释。建议在 T-008 全局收尾里提取成组件，或给一张专门的任务单。
3. **文案未集中到 `src/lib/copy.ts`（`ui.md` §10.9）**：`src/lib/**` 不在 T-004 可改目录内，本次文案散落在 `page.tsx` 与 `EmptyState` 的调用处。建议 T-008 一并集中。
4. **空状态「清除关键词」按钮只在有关键词时出现**：`ui.md` §5.2 写的是「两个次要按钮并排」。若只带标签而命中 0（当前数据下每个标签都 ≥1 部，正常路径不可达），「清除关键词」会是一条无意义的链接，因此按条件渲染（`page.tsx:125-129`）。如果要求两种按钮恒定出现，请告知。
