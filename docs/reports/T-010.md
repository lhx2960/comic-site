### 2. CI 各步骤在干净副本上真实跑通（基线 `925baf6`）

本机 `node_modules` 是 pnpm 硬链接到全局 store，沙箱内 node 读硬链接文件会被拒（`EPERM`，`nlink` 为 2 的文件全失败），因此验证改在 `%TEMP%` 的干净副本里做：`git archive HEAD` 导出 → `pnpm install` 从零安装 → 依次跑四条命令。

```
pnpm install --frozen-lockfile --offline
  Ignored build scripts: esbuild, unrs-resolver.
  Done in 13.2s using pnpm v10.24.0          → exit 0

pnpm type-check  → tsc --noEmit              → exit 0
pnpm lint        → eslint .                  → exit 0
pnpm test        → Test Files 15 passed (15)
                   Tests 139 passed (139)    → exit 0
pnpm build       → Next.js 15.5.26
                   ✓ Compiled successfully in 6.2s
                   ✓ Generating static pages (4/4)  → exit 0

Route (app)                                   Size  First Load JS
┌ ƒ /                                        981 B         112 kB
├ ○ /_not-found                              131 B         102 kB

├ ƒ /comics/[slug]                         2.12 kB         113 kB
└ ƒ /comics/[slug]/[chapter]               4.87 kB         116 kB
```

顺带澄清两件事：

- **pnpm 版本锚点**：`pnpm -v` 报 11.25.0（运行时兜底 shim），但实际安装器是 **pnpm 10.24.0**（离线安装输出自证，`node_modules/.modules.yaml` 里 `packageManager: pnpm@10.24.0`），CI 据此钉 10.24.0。
- **`Ignored build scripts: esbuild, unrs-resolver` 无害**：在这两个包的脚本被跳过的情况下，type-check / lint / test / build 依旧全绿——即 CI 用默认设置即可，不需要 `pnpm approve-builds`。

### 3. 回滚步骤的本地等价演练（在 `%TEMP%` 副本执行）

Vercel 的 Promote/rollback 本质是「把生产指回另一份构建产物」。用两次真实构建当新旧两个 deployment，切换产物后重新起服务并探测：

```
制品 A（= 线上旧版本）BUILD_ID = ah4ruBmt9DxjYk4vl1jb8
模拟新部署 → 制品 B      BUILD_ID = 0YJaOoMSY6jz6FaPoA2Av

第 1 次探测（在跑 B）:
  probe=_buildManifest.js | served 0YJaOoMSY6jz6FaPoA2Av -> HTTP 200
                          | other  ah4ruBmt9DxjYk4vl1jb8 -> HTTP 404
                          | home html contains self buildId = True

回滚：删 .next → 把备份的制品 A 移回 → .next/BUILD_ID = ah4ruBmt9DxjYk4vl1jb8

第 2 次探测（回滚后在跑 A）:
  probe=_buildManifest.js | served ah4ruBmt9DxjYk4vl1jb8 -> HTTP 200
                          | other  0YJaOoMSY6jz6FaPoA2Av -> HTTP 404
                          | home html contains self buildId = True
```

结论：换掉构建产物并重启后，服务端服务的确实是切回去的那一份（双向可证），与生产上 `vercel rollback <url>` / Dashboard Promote 是同一操作。演练中踩到的坑（`next.CMD` 被杀后 node 子进程仍占端口，导致第二次探测打到旧进程）已写进 `docs/ops.md` §6.2，避免下次重复。
