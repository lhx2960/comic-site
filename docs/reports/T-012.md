## 改动的文件（严格限于可改目录）

| 路径 | 做了什么 |
| --- | --- |
| `src/app/comics/[slug]/[chapter]/page.tsx` | 三种结局都在本页直接渲染：`comic-missing` → `<ComicNotFound />`、`chapter-missing` → `<ChapterNotFound slug={slug} />`、正常 → `<ReaderStrip />`；**不再调用 `notFound()`**（`:67-87`）。`generateMetadata` 也按同一判定给出「这一话不存在 / 这部漫画不存在」标题（`:35-46`） |
| `src/app/comics/[slug]/[chapter]/not-found.tsx` | 改成服务端组件并接受可选的 `slug`（由页面传入，出口是「返回详情 / 返回首页」；被边界渲染时收不到 props 就退化为「返回首页」）；同时把三态判定 `classifyReaderRoute()` 与 `ReaderRouteOutcome` 放在这里（`:21-48`） |
| `tests/components/chapter-route-outcome.test.ts` | 新增 10 条：漫画不存在优先、数据无此话、7 种非法话号、正常阅读 |
| `tests/components/route-not-found.test.tsx` | 改为直接传 `slug` prop（不再需要 `useParams` 桩件），并显式断言话级文案**不含**「这部漫画不存在」（与 slug 级的区别） |

**为什么判定函数不放在 `page.tsx`**：Next 对本项目 page 文件的具名导出有严格校验（只允许
`default` / `metadata` / `generateMetadata` / `dynamic` 等），我第一版把它 export 出去后
`next build` 直接失败（`TS2344: Property 'classifyReaderRoute' is incompatible with index signature`），
所以挪到了同目录的 not-found 文件里——那里既能被单测 import，也不影响它作为边界文件。

**为什么连「漫画不存在」也改成直接渲染**：中途实测到边界选择会随组件形态变化——
把话级 not-found 从客户端组件改成服务端组件后，`/comics/nope/1` 在 prod 下从
「这部漫画不存在」变成了「这一话不存在」（落到话级边界）。这说明**边界选择本身不稳定**，
所以两条都改成直接渲染，彻底不依赖它。这也是任务单第 1 条推荐的思路。

## 遗留问题与建议

1. **`notFound()` 现在只剩两处使用者**：详情页（`comics/[slug]/page.tsx`，漫画不存在时）与
   根级未定义路由。话级 not-found 文件仍然作为边界存在（Next 自动识别），但正常流程不再依赖它；
   如果后续有任务想统一口径，可以把详情页也改成直接渲染作品级空状态，那样边界选择就完全不影响文案了。
   ——需要你点头才做，不在本任务范围。
2. **话级空状态的配色**：现在渲染的是浅色站点域的空状态（与 dev 下的表现一致）。
   `ui.md` §5.4 把阅读页的等价空状态画在深色域里；若要改成深色，需要把 `[chapter]` 的这段
   包进 `data-theme="reader"` 容器并复查对比度，属设计口径问题，建议并入后续收尾任务。
3. **T-009 报告的 F-04 依旧存在**：跑 `pnpm e2e`（走 `pnpm dev`）会改写 `.next`，之后如需生产
   服务必须重新 `pnpm build`——本轮我按这个顺序执行，已无问题，但 CI 里若两者并行仍需规避。
