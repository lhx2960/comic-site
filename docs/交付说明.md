## 4. 怎么跑

```bash
pnpm install          # 安装依赖
pnpm dev              # 本地开发（http://localhost:3000）
pnpm build && pnpm start   # 生产构建 + 启动（发布形态）
pnpm test             # 单元/组件测试
pnpm e2e              # 端到端（会自动 build + start，跑在 3100）
pnpm generate:sample-data  # 重新生成示例数据与占位图（幂等）
```

手机真机试玩：`pnpm dev` 后，用手机连同一个 Wi-Fi 打开 `http://<电脑局域网IP>:3000`。

## 5. 本地注意事项（踩过的坑）

1. **同一时刻只跑一份 E2E**（D-023）：E2E 的 webServer 会 `pnpm build` 并占用 3100 端口；两份并行会写坏 `.next`，表现为「Could not find a production build」或偶发红灯。跑之前确认没有残留 node 进程。
2. **E2E 必须跑生产构建**（D-019）：`playwright.config.ts` 已固定为 `pnpm build && pnpm start`。历史教训：同一份代码在 `next dev` 下 102/102，在 prod 下暴露了 404 文案不一致、点击被吞等问题。
3. **Next 遥测**：`next.config.mjs` 顶部关闭遥测（本机 `pnpm build` 会因写 `%APPDATA%` 失败而中断）。
4. **`.pnpm-store/`**、`test-results/`、`playwright-report/`、`*.tsbuildinfo` 已加入 `.gitignore`。

## 7. 下一步建议（按性价比排序）

1. **登录 Vercel 部署一次**（`docs/ops.md`），拿到预览 URL 后你在真机上过一遍阅读体验。
2. **接入真实内容**：数据模型与访问层已就绪，`Comic.cover` 可直接换成真实 2:3 封面；换数据源只需改 `src/lib/data/`（契约不变）。
3. **把 E2E 纳入 CI 门禁**：`ci.yml` 里 E2E 步骤预留了开关，本地已稳定（耗时约 1.2 分钟），建议打开。
4. **SEO/语义收尾**：按 D-017 用路由组把 404 路径移出 Suspense 边界，恢复 404 状态码。
5. **C 期起步**：账号 → 收藏 → 评论 → 付费，每项单独出 PRD 与契约；本期结构与契约已为它们留好边界。
